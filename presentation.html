📚 Sistem Informasi Perpustakaan

Sistem Peminjaman
Buku Perpustakaan

Sebuah platform digital berbasis web untuk mengelola peminjaman & pengembalian buku dengan sistem approval berlapis, manajemen stok real-time, dan kalkulasi denda otomatis.

🛠️ Laravel 12 + TailwindCSS + Alpine.js
🗄️ MySQL + Eloquent ORM
⚡ Vite Build Tool
👥 Role-Based Access Control
01 — Latar Belakang
Mengapa Sistem Ini Dibangun?
Perpustakaan masih bergantung pada pencatatan manual yang rawan kesalahan, tidak transparan, dan sulit diaudit.
📋

Pencatatan Manual

Proses peminjaman masih dicatat di buku besar, rentan kehilangan data dan human-error.

⏰

Tidak Ada Monitoring

Sulit memantau buku yang sedang dipinjam, tenggat waktu, dan status pengembalian secara real-time.

💰

Denda Tidak Konsisten

Perhitungan denda keterlambatan dilakukan manual sehingga hasilnya tidak akurat dan tidak transparan.

📦

Stok Tidak Terkontrol

Tidak ada sistem untuk mencegah peminjaman berlebih (over-borrowing) saat stok kritis.

🔐

Tidak Ada Otorisasi

Siapa saja dapat mengubah data buku atau anggota tanpa sistem hak akses yang jelas.

📊

Laporan Sulit

Menghasilkan laporan peminjaman membutuhkan waktu lama karena data tersebar dan tidak terstruktur.

02 — Tujuan Sistem
Apa yang Ingin Dicapai?
✅

Digitalisasi Proses Peminjaman

Menggantikan sistem manual dengan platform web yang efisien, terdokumentasi, dan dapat diakses kapan saja.

🔄

Approval Workflow Berlapis

Admin dapat menyetujui atau menolak setiap permintaan pinjam dan kembali, memastikan akuntabilitas penuh.

📦

Manajemen Stok Real-Time

Stok buku dikurangi saat pinjam disetujui dan dikembalikan saat pengembalian disetujui, mencegah over-borrowing.

💸

Kalkulasi Denda Otomatis

Sistem otomatis menghitung denda Rp 5.000/hari untuk keterlambatan saat admin menyetujui pengembalian.

📈

Laporan & Ekspor Data

Admin dapat melihat laporan lengkap dan mengekspor data peminjaman ke format CSV dengan satu klik.

🛡️

Keamanan Berbasis Peran

Role-Based Access Control (RBAC) memastikan Admin dan User hanya dapat mengakses fitur yang relevan.

03 — Ruang Lingkup & Pengguna
Siapa Pengguna Sistem?
👑

Admin (Pustakawan)

Memiliki akses penuh ke seluruh fitur sistem.

  • ✓ Dashboard statistik global
  • ✓ CRUD buku & kategori
  • ✓ Kelola anggota (promote, hapus)
  • ✓ Setujui / tolak peminjaman
  • ✓ Setujui pengembalian + hitung denda
  • ✓ Laporan + ekspor CSV
  • ✓ Filter & cari data peminjaman
📖

User (Mahasiswa/Anggota)

Akses terbatas sesuai peran anggota perpustakaan.

  • ✓ Dashboard status pribadi
  • ✓ Lihat & cari katalog buku
  • ✓ Request peminjaman buku
  • ✓ Request pengembalian buku
  • ✓ Lihat riwayat peminjaman sendiri
  • ✓ Lihat status denda
  • ✗ Tidak bisa akses data orang lain

🔒 Ruang Lingkup

Sistem ini mencakup: manajemen koleksi buku, kategori, anggota, peminjaman, pengembalian, denda, dan laporan. Tidak mencakup: pembayaran online, notifikasi email/SMS, atau manajemen aset fisik lainnya.

04 — Perjalanan Pengembangan
4 Deliverable, 1 Final Product
Sistem dibangun secara iteratif melalui empat fase dengan mekanisme feedback di setiap tahap.
D1
SRS
Software Requirements Specification. Mendefinisikan kebutuhan fungsional & non-fungsional, use-case diagram, dan batasan sistem.
D2
Desain Sistem
ERD, arsitektur sistem (MVC), wireframe UI, alur data, dan desain skema database MySQL.
D3
MVP + Testing
Minimum Viable Product dengan fitur inti: auth, CRUD buku, peminjaman dasar. Pengujian awal dilakukan, ditemukan beberapa gap.
D4
Final Product
Sistem lengkap: approval workflow, kalkulasi denda, ekspor CSV, RBAC penuh, soft-delete, dan perlindungan data terintegrasi.
D1 – SRS
  • • Identifikasi kebutuhan
  • • Use case diagram
  • • Stakeholder analysis
  • • Functional & non-functional req

  • • Wireframe per halaman
  • • Skema DB MySQL

07 — Fitur Utama Final Product
Apa Saja yang Bisa Dilakukan?
🔐

Autentikasi & RBAC

Login/register via Laravel Breeze. Role admin vs user menentukan akses ke seluruh halaman dan aksi sistem.

📚

CRUD Buku & Kategori

Admin dapat tambah, edit, hapus (dengan Soft Delete + proteksi buku aktif) buku dan kategori. Filter by kategori & search.

✅

Approval Workflow Peminjaman

User request → status "Menunggu" → Admin approve/reject → status "Dipinjam". Stok dikurangi saat disetujui.

🔄

Approval Workflow Pengembalian

User klik Kembalikan → status "Menunggu Kembali" → Admin setujui → stok dikembalikan + denda dihitung.

💸

Kalkulasi Denda Otomatis

Saat pengembalian disetujui, sistem menghitung Rp 5.000/hari keterlambatan menggunakan Carbon date diff.

📊

Dashboard Statistik

Admin: 8 statistik global (total user, buku, peminjaman, pending, aktif, terlambat, denda, tunggu kembali). User: statistik pribadi.

🔍

Filter & Pencarian Laporan

Admin dapat filter laporan peminjaman by: nama peminjam, status, dan flag khusus "buku terlambat".

📥

Ekspor CSV

Export seluruh data laporan peminjaman ke file CSV UTF-8 BOM dengan satu klik, siap dibuka di Excel.

👥

Manajemen Anggota

Admin dapat melihat daftar anggota, promote ke Admin, atau hapus akun (dengan proteksi: tidak bisa hapus jika masih ada peminjaman aktif).

🛡️

Proteksi Data Terintegrasi

Buku tidak bisa dihapus jika sedang dipinjam. Akun user tidak bisa dihapus jika masih ada pinjaman aktif. Soft Delete pada buku.

12 — Penyempurnaan D3 → D4
Apa yang Berubah dari MVP ke Final?

❌ D3 — MVP (Versi Awal)

  • Tidak ada sistem approval — peminjaman langsung disetujui
  • Tidak ada kalkulasi denda — tidak ada konsekuensi keterlambatan
  • Database SQLite — tidak cocok untuk produksi
  • Tidak ada Role-Based Access Control (semua user sama)
  • Tidak ada filter/pencarian di laporan peminjaman
  • Tidak ada ekspor data/laporan CSV
  • Buku bisa dihapus meski sedang dipinjam
  • Akun bisa dihapus meski masih ada peminjaman aktif
  • Stok tidak terkontrol — bisa over-borrowing
  • Dashboard tidak ada — langsung ke halaman buku

✅ D4 — Final Product

  • Approval Workflow 2 tahap: pinjam & kembali (admin harus approve)
  • Kalkulasi denda otomatis Rp 5.000/hari via Carbon
  • Migrasi ke MySQL untuk produksi yang robust
  • RBAC penuh: Admin vs User dengan middleware & bouncer check
  • Filter by nama, status, flag overdue pada halaman laporan
  • Ekspor laporan ke CSV UTF-8 BOM (kompatibel Excel)
  • Proteksi: buku dengan pinjaman aktif tidak bisa dihapus
  • Proteksi: akun dengan pinjaman aktif tidak bisa dihapus
  • Stok dikurangi saat approval — mencegah race condition
  • Dashboard statistik lengkap untuk admin (8 metrik) & user (5 metrik)
